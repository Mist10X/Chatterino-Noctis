# Noctis Moderator — управление модулем

Отдельный ограниченный модуль публичной сборки; Personal-автоответчик не используется.

1. В `module-spec.json` укажи Twitch **ID**, не ник, в `allowed_twitch_ids`. Для удаления доступа убери ID.
2. При любом изменении увеличь `revision`, а при изменении поведения модуля также увеличь `module_version`. `matcher.lua` — обновляемый алгоритм выбора локального правила.
3. Подпиши пакет из Windows-профиля владельца:

   ```powershell
   python tools/moderator/sign-module.py --spec tools/moderator/module-spec.json --output moderator/module.json
   ```

4. После отдельного согласия на публикацию обнови только `moderator/module.json` в основной ветке публичного репозитория. Не нужен новый GitHub Release или новая версия EXE.

Клиент запрашивает файл без Twitch-токена/ID при входе и затем каждые 5 минут;
проверяет Ed25519-подпись, срок действия и ревизию. Невалидный/недоступный
список закрывает доступ. Список действует до 90 дней — обновляй его с новой
ревизией до истечения. При недоступности Twitch проверка роли тоже закрывает
отправку. Список модераторских каналов обновляется через штатный Helix API
примерно раз в минуту. На отправке сверяются текущий аккаунт, роль канала и
действующий список. Нет ручного канала, вкладки всех каналов, смены отправителя,
команд слэша или повторной отправки. Разрешения не кешируются между запусками.

Секретный ключ хранится вне репозитория в защищённом DPAPI-файле
`%LOCALAPPDATA%\NoctisModeratorSigning\ed25519.dpapi`. Не публиковать
этот файл, не передавать его третьим лицам, не заменять ключ без новой сборки.
Подписанный пакет и список ID публично читаемы, но нельзя подменить их без
ключа. Контроль действует в официальной сборке; полностью исключить правку
изменённого открытого клиента без сервера невозможно.

Lua-модуль получает только нормализованное сообщение и локальные правила
канала, возвращает индекс правила. Нет доступа к файлам, сети, токенам, другим
аккаунтам, нативным модулям или командам. Размер памяти и число инструкций
ограничены. Новые алгоритмы выбора можно обновлять отдельно, а новый тип
события/действия (например, Twitch-награда или мут) сначала требует добавления
контролируемого API в хост-клиент, затем его поведение можно обновлять модулем.
Сейчас разрешено только отправлять обычный ответ на живое сообщение.

См. [указание автора](AUTHOR-NOTICE.md). Уведомление находится в файлах, не в интерфейсе.
